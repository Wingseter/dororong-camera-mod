# Problem 2 (코드 영역 패치 불가) 분석 및 해결 아이디어

본 문서는 `README.md`에 기술된 펌웨어 코드 영역(0x01xxxx) 패치 실패 문제에 대한 심층 분석과 검증/해결 아이디어를 정리한 문서입니다.

## 1. 실험 계획(Experimental Plan)에 대한 논리적 피드백

작성하신 계획 중 **"실험 1: 0x0B4000 패딩 영역 테스트"에는 논리적인 맹점**이 있습니다.
* 이미 데이터 영역(0x07xxxx ~ 0x0Cxxxx)은 어떤 패치를 해도 정상 작동(✅ 성공)한다는 사실이 검증되었습니다. 따라서 `0x0B4000` 영역의 1바이트를 수정하는 것은 기존에 성공했던 '데이터 영역 패치'를 한 번 더 반복하는 것에 불과하며, 핵심 타겟인 **코드 영역(0x01xxxx)의 분리 보호 여부나 XOR 범위를 증명해 주지 못합니다**.
* **수정 제안**: 코드 영역의 XOR/보호 여부를 블랙박스 테스트하려면, 반드시 **코드 영역(0x01xxxx ~ 0x06xxxx) 내부에 존재하는 무해한 바이트(예: NOP 구문 `0x00000000` 패딩, 텍스트 문자열의 자투리 등)**를 찾아 1바이트 변경 테스트를 수행해야 합니다.

## 2. 해결 및 검증 아이디어 (접근법의 전환)

수차례의 Brick과 복구(CH341A) 과정은 물리적 시간 소모와 칩 스트레스가 큽니다. 리버스 엔지니어링 관점에서 다음 아이디어들을 우선적으로 추천합니다.

### 💡 아이디어 A: 물리적 실험 전, CH341A 직접 쓰기를 1순위(Exp 3 -> 1)로 격상
문제의 원인이 **(1) SD 업그레이드 루틴** 때문인지, 아니면 **(2) 매번 전원을 켤 때마다 도는 부트로더의 무결성 검증** 때문인지 완벽히 격리해야 합니다.
1. 코드 영역(0x01FDD4 등) 단 1곳만 패치한 바이너리를 만듭니다. (GPNV XOR 패치 적용 안 함)
2. SD 업그레이드를 생략하고, CH341A를 이용해 SPI 롬에 다이렉트로 굽습니다.
3. **결과 해석**:
   * **만약 부팅 성공 시**: 부트로더는 코드 영역을 검사하지 않습니다. 즉, **SD 업그레이드 함수(`FUN_00041678`)**가 코드 영역 덮어쓰기를 방어하거나 자체 실패를 유발하는 범인입니다.
   * **만약 여전히 Brick 발생 시**: SD 방식과 무관하게, **부트로더(`GPNVBtLdr` 등)가 부팅 시점마다 코드 영역의 무결성(Signature/CRC/XOR)을 깐깐하게 검증**하고 있는 것입니다. 이 경우 부트로더를 분석하거나, 체크섬 해시 알고리즘을 완벽히 맞춰주어야만 패치가 가능해집니다.

### 💡 아이디어 B: Python 스크립트를 이용한 GPNV XOR 검증 범위 '역산 (Brute-force)'
벽돌(Brick)을 만들지 않고도 GPNV XOR의 범위를 수학적으로 찾아낼 수 있습니다.
* 이미 원본 바이너리 파일과 헤더에 적힌 GPNV XOR 값(offset 0x08 부근 예상)을 알고 계십니다.
* 짧은 Python 스크립트를 작성하여, 특정 시작 주소(`0x010000` 등)부터 종료 주소를 1바이트씩 늘려가면서 XOR Sum이나 CRC를 계산하게 합니다.
* 루프를 돌다가 파일 헤더에 적힌 Checksum 값과 정확히 일치하는 범위(End Address)가 튀어나온다면, 그 범위가 곧 Bootloader나 Updater가 검증하는 **코드 영역 범위**임을 100% 확신할 수 있습니다.

### 💡 아이디어 C: Ghidra 정적 분석으로 검증 알고리즘 추출
가장 근본적인 해결책입니다.
1. **부트로더 분석**: 메모리 맵 제일 처음(`0x000000 ~ 0x003000`)에 위치하는 부트로더를 디스어셈블하여, 플래시에서 RAM으로 펌웨어를 복사한 직후 수행하는 루프(Loop)를 찾습니다.
2. **SD 업그레이더 분석**: `FUN_00041678` 함수에서 플래시 메모리 특정 Address 범위(예: `0x01xxxx` ~ `0x06xxxx`)에 쓰기 작업을 수행하기 직전/직후에 에러 코드를 반환하는 분기가 있는지 확인합니다.

## 3. 요약된 다음 단계 액션 리스트 (Next Steps)

1. **[소프트웨어]** Python 스크립트로 0x010000 구간부터 XOR 누적 합을 계산해, 헤더의 체크섬과 일치하는 길이를 역추적하기 (Brute-force XOR Check). 일치하면 해당 영역의 체크섬 로직을 파악한 것입니다.
2. **[하드웨어]** 소프트웨어 분석이 벽에 부딪히면, 코드 영역 내 무해한 1바이트 패치를 **CH341A로 직접 플래싱**하여 부트로더 단의 서명 검증이 존재하는지(Brick) 없는지(부팅 성공) 단번에 규명하기.
3. **[분석]** Ghidra를 열어 부트로더 섹션(맨 앞단 16KB 등)에서 에러를 뿜고 멈춰버리는 무결성 검증 반복문(Checksum loop) 찾아내기.
