# Problem 2: 펌웨어 코드 영역(0x01xxxx) 패치 시 부팅 불가

> 일시: 2026-03-29
> 상태: 미해결 — 코드 영역 패치가 SD 업그레이드로 2회 연속 brick
> 우선순위: 최상 (Problem 1 해결의 전제조건)

## 문제

펌웨어의 **ARM 코드 영역(0x01xxxx)**을 수정하고 SD 업그레이드하면 카메라가 부팅되지 않음.
데이터/리소스/설정 영역(0x07xxxx~0x0Cxxxx)은 모두 정상 패치 가능.

## 증거

### SD 업그레이드 성공 이력 (데이터 영역)

| 패치 대상 | 오프셋 | 결과 |
|-----------|--------|------|
| UVC Brightness 기본값 | 0x08279C, 0x08279E | ✅ 성공 |
| UVC PU bmControls | 0x0822AA | ✅ 성공 |
| JPEG Q-테이블 | 0x084438, 0x08447D | ✅ 성공 |
| 설정 블록 (CRC32 포함) | 0x0C2000~0x0C3A00 | ✅ 성공 |
| 부팅 화면 JPEG | 0x0AA000 | ✅ 성공 |
| 버전 문자열 | 0x079E6C | ✅ 성공 |

### SD 업그레이드 실패 이력 (코드 영역)

| 시도 | 패치 오프셋 | 내용 | 결과 |
|------|-----------|------|------|
| 1차 | 0x1FDD4, 0x1FDD8, 0x1C764, 0x1C870 | 해상도 1600→1280, 1200→720 (4곳) | ❌ brick |
| 2차 | 0x1FDD4, 0x1FDD8 | 해상도 1600→1280, 1200→720 (2곳만) | ❌ brick |

**~~패턴: 0x01xxxx 영역 패치 = 항상 brick~~**

**해결 (2026-03-29)**: 코드 영역 내 무해한 문자열(0x041A18 "Upgrading"→"Xpgrading") 1바이트 패치 → SD 업그레이드 → **부팅 성공**.
코드 영역 자체는 보호되지 않음. GPNV XOR 변경 없이도 통과.
→ 이전 720p brick의 원인은 코드 보호가 아닌 **해상도 패치 런타임 문제** (4:3 still 파이프라인에 16:9 크기 주입).

## 원인 후보

### 1. 부트로더가 코드 영역을 별도 검증 (가장 유력)

부트로더(0x000~0x003000)가 메인 코드 영역에 대해 SD 업그레이드 바이트합과 별개로
추가 무결성 검증을 수행할 가능성:

- **섹터별 XOR/CRC**: GPNV XOR(offset 0x08)의 범위가 코드 영역만 포함
- **코드 서명**: ARM 벡터 테이블이나 코드 영역에 별도 해시
- **부트로더 체크섬**: `GPNVBtLdr` 복구 루틴이 코드 무결성 검증 후 실패 시 정지

근거:
- 데이터 영역(0x07~0x0C)은 GPNV XOR 변경 없이도 패치 성공
- Phase 2 Q-테이블(0x084438) 패치 시 GPNV XOR 불변 → 데이터 영역은 XOR 범위 밖
- 코드 영역(0x01xxxx) 패치 시 GPNV XOR 차분 업데이트 적용 → 하지만 brick

### 2. GPNV XOR 범위 판정 오류

0x01FDD4가 GPNV XOR 범위 안인지 밖인지 확인되지 않음:
- **범위 안이라면**: 차분 업데이트가 올바르게 적용되어야 하나 brick
- **범위 밖이라면**: 차분 계산에 포함하면 안 되는데 포함시켜 GPNV 체크섬 오염

### 3. SD 업그레이드 프로세스의 코드 영역 보호

SD 업그레이드 함수(FUN_00041678)가:
- 특정 영역만 쓰기 허용 (코드 영역 잠금)
- 또는 코드 영역 쓰기 후 별도 검증 실패

## 확인 실험 계획

### 실험 1: GPNV XOR 범위 판정

코드 영역의 **무해한 바이트**(NOP 등이 아닌 패딩/미사용 바이트)를 1바이트만 변경하여
GPNV XOR을 **변경한 버전**과 **변경하지 않은 버전** 2개를 SD 업그레이드로 테스트.

- 버전 A: GPNV XOR 차분 업데이트 적용 → 부팅 되면 범위 안
- 버전 B: GPNV XOR 그대로 유지 → 부팅 되면 범위 밖
- 둘 다 brick → 코드 영역 자체가 보호됨

**패치 대상**: 펌웨어 코드 영역 내 안전한 위치 (예: 0x0B4000~0x0C2000 패딩 영역은 코드가 아님)

→ 먼저 **0x0B4000 패딩 영역**(56KB 0x00)에서 1바이트 변경 테스트.
이 영역은 코드도 데이터도 아닌 빈 공간이므로 가장 안전.

### 실험 2: 코드 영역 최소 변경

실험 1에서 코드 영역 보호가 아님이 확인되면:
- 0x012000 이후의 실제 코드 영역에서 1바이트만 변경 (예: 문자열 상수 1글자)
- 부팅 여부로 코드 영역 패치 가능성 확인

### 실험 3: CH341A 직접 쓰기 비교

SD 업그레이드가 코드 영역을 보호한다면:
- CH341A로 동일 패치를 직접 SPI에 쓰기
- 부팅 되면 → SD 업그레이드의 코드 보호 확인
- 안 되면 → 부트로더 자체의 코드 검증
