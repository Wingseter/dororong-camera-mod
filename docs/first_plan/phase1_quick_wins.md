# Phase 1: Quick Wins — 결과

> 일시: 2026-03-29
> 결과: UVC 패치 효과 미미 → 방향 전환 필요

## 적용한 패치 (3바이트)

| 오프셋 | 변경 | 목적 |
|--------|------|------|
| 0x08279C | 0x10→0x80 | Brightness 현재값 16→128 |
| 0x08279E | 0x10→0x80 | Brightness 기본값 16→128 |
| 0x0822AA | 0x01→0x3F | UVC PU bmControls 6개 컨트롤 활성화 |

## 테스트 결과

### Brightness 기본값 변경 — 효과 없음

동일 피사체 비교 (Windows 카메라 앱):

| 지표 | Before (16) | After (128) | 변화 |
|------|-------------|-------------|------|
| 밝기 평균 | 80.3 | 72.8 | -7.5 (오히려 감소) |
| 밝기 중간값 | 88.0 | 76.0 | -12.0 |
| 밝기 표준편차 | 29.8 | 24.3 | -5.5 |

**원인 추정:**
1. Windows 카메라 드라이버가 UVC GET_DEF 값을 무시하고 자체 기본값 사용
2. 또는 0x08279E가 UVC 응답에 실제 사용되지 않는 오프셋
3. AE(자동노출)가 장면에 맞춰 밝기를 자동 조절하므로 기본값이 무시됨

### UVC PU 컨트롤 확장 — 표시만 됨

Windows 카메라 앱에서 새로 나타난 컨트롤:
- 밝기: 1~100 슬라이더 (기존에도 있었음)
- 채도(Saturation): 0 or 100 (토글 형태)
- 선명도(Sharpness): 0 or 100 (토글 형태)

**하지만 조절해도 화면 변화 없음.**

**원인:**
bmControls 비트를 켜면 호스트 OS에 "이 컨트롤 지원합니다"라고 광고함.
하지만 실제 SET_CUR 요청을 받았을 때 ISP 파라미터를 변경하는 **핸들러 코드가 Brightness밖에 구현되어 있지 않음.**
→ 디스크립터 수정만으로는 실제 기능 추가 불가.

## 교훈

1. **UVC 디스크립터 패치는 표면적 변경** — 컨트롤 UI는 나타나지만 실제 동작하지 않음
2. **UVC 기본값은 OS가 무시할 수 있음** — 특히 AE가 활성화된 카메라에서
3. **진짜 화질 개선은 카메라 내부 ISP 파라미터 직접 수정** — UVC 경유가 아닌 펌웨어 레벨

## 방향 전환

UVC 웹캠 모드 패치로는 실질적 화질 개선 불가.
→ **카메라 독립 모드(SD 카드 녹화/촬영)의 ISP 직접 튜닝**으로 전환.
→ Phase 2 (JPEG 품질), Phase 3 (ISP 기본값)이 실제 효과 있는 경로.
