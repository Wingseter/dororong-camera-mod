## 4. 메인 펌웨어 벡터 테이블

### 위치: 0x012C00 (첫 non-zero 데이터)

| 벡터 | ARM 명령어 | 타겟 주소 | 설명 |
|------|-----------|----------|------|
| [0] Reset | `LDR PC, =0x3C` | 0x0000003C | 메인 코드 진입점 |
| [1] Undef | `LDR PC, =0x250` | 0x00000250 | 미정의 명령 핸들러 |
| [2] SWI | `LDR PC, =0x25C` | 0x0000025C | 소프트웨어 인터럽트 |
| [3] Prefetch | `LDR PC, =0x268` | 0x00000268 | 프리페치 어보트 |
| [4] Data Abort | `LDR PC, =0x274` | 0x00000274 | 데이터 어보트 |
| [5] Reserved | `B .` (무한루프) | 0x012C14 | 사용 안 함 |
| [6] IRQ | `LDR PC, =0x280` | 0x00000280 | 인터럽트 핸들러 |
| [7] FIQ | `LDR PC, =0x2B0` | 0x000002B0 | 빠른 인터럽트 |

**분석**: 타겟 주소가 0x3C~0x2B0 범위 → 부트로더가 펌웨어를 **RAM 0x0 번지**에 복사한 후 점프. SPI Flash에서 직접 실행하지 않음.

### 부트로더 벡터 (0x000200)

| 벡터 | 타겟 | 설명 |
|------|------|------|
| Reset | `LDR PC, =0x001F8024` | SRAM(0x1F8000) + 0x24 오프셋 |
| [1]-[4] | `MOV PC, #0` | 미사용 (NOP) |
| [5] | `B .` | 무한루프 |

부트로더 실행 흐름: Flash 0x200 → SRAM 0x1F8000에 복사 → 0x1F8024에서 실행 시작

## 7. GPRS v2 리소스 인덱스

### 위치: 0x089E00

```
Magic: "GPRS"
Version: 2
```

### 구조

- **영어 문자열 테이블**: base + 0x5E4 = 0x08A3E4 ("English", "video mode", ...)
- **언어별 렌더링 테이블 6개**: base + 0xC686 ~ 0xFD26
  - 각 테이블 크기: 0xAF0 (2,800바이트)
  - 엔트리 형식: `(pixel_width: u32, string_offset: u32)`
  - string_offset은 base(0x089E00) 기준 상대 오프셋

### 다국어 지원

6개 언어 지원. 비영어 문자열은 내장 비트맵 폰트의 글리프 인덱스로 인코딩됨.

- 영어: ASCII 문자열 (0x08A3E4~)
- 비영어 (5개): 단일 바이트 글리프 코드 (0x01~0x19 범위 값)
- 폰트 데이터: 0x08C000~0x0A8000 영역 (엔트로피 3.0-4.5, 글리프 너비/인덱스)

**폰트 특성:**
- 글리프 너비: 0~25 픽셀 (160px LCD에 맞는 가변폭)
- 약 3,150개 non-zero 엔트리 → CJK 포함 가능
- 값 분포: 0(139), 4(12), 6(10), 11(13), 14(10), 17(6), 18(7)

## 8. SD 업그레이드 분석 수정

### 이전 분석의 오류

`JH_5307_test.bin`에서 변경한 위치(0x041E90)는 **펌웨어 코드 내 하드코딩된 빌드 문자열**이지, 업그레이드 함수가 비교하는 **파일 offset 0x16이 아님**.

### 업그레이드 버전 비교 재분석

```c
// 업그레이드 함수 (Ghidra 디컴파일):
cmp = FUN_00018300(file_data + 0x16, "2025004291200", 12);
if (cmp != 0) {
    return 1;  // 버전 다름 → 업그레이드 진행
}
```

- `file_data + 0x16`: SD 카드 파일의 offset 0x16
- 현재 펌웨어 offset 0x16: `00 00 FF 00 01 01 00 00 00 FF 00 80` (GPNV 헤더 데이터)
- 비교 대상: `"2025004291200"` (현재 펌웨어의 빌드 ID, 코드에 하드코딩)

두 값이 **이미 다르므로** → 원본 펌웨어를 그대로 `JH_5307.bin`으로 SD에 넣어도 **업그레이드가 트리거됨**.

### 수정된 업그레이드 테스트 전략

```
1단계: 원본 firmware_backup_1.bin → JH_5307.bin으로 복사 → SD에 넣고 부팅
  - 체크섬 통과 여부 확인 (원본이므로 체크섬 일치해야 함)
  - "Upgrading firmware..." 표시되면 → 성공

2단계: 수정된 펌웨어 (Brightness 등 변경) → JH_5307_mod.bin
  - offset 0x08의 바이트합 체크섬 재계산 필요
  - 파일 전체 바이트 합산 → offset 0x08에 기록
```

## 9. 체크섬 분석 현황

### GPNV 헤더 체크섬 (offset 0x08)

```
현재 값: 0x0BD04FA2
```

**시도한 알고리즘 (전부 불일치):**

| 방법 | 범위 | 결과 |
|------|------|------|
| 바이트 합산 | 전체 (체크섬 제외) | 0x07704941 |
| 바이트 합산 | 0x0C~EOF | 0x077047DE |
| 바이트 합산 | 0x12000~0xB4000 | 0x03AD0D5E |
| 32비트 워드 합 | 전체 (체크섬 제외) | 0xE2EF7180 |
| 16비트 하프워드 합 | 전체 (체크섬 제외) | 0xDF7DCDD3 |
| CRC32 (standard) | 전체 (체크섬 제외) | 0x1DD88896 |
| CRC32 (Castagnoli) | 전체 | 불일치 |
| Fletcher-32 | 전체 (체크섬 제외) | 0x053DAD54 |
| 부정합(-sum) | 전체 (체크섬 제외) | 0xF88FB6BF |

**추정**: Generalplus 자체 알고리즘 사용 가능성. 부트로더 코드의 Ghidra 심층 분석 또는 UART 디버그 출력에서 확인 필요.

### 실용적 우회 전략

1. **원본 파일 SD 테스트**: 체크섬이 이미 맞으므로 업그레이드 동작 확인 가능
2. **CH341A 직접 쓰기**: 부트로더를 건드리지 않으면 GPNV 체크섬 무관할 수 있음
3. **부트로더 복구**: `GPNVBtLdr Recover well done` 메시지 존재 → 체크섬 실패 시 자동 복구 가능성

## 11. DOOM 포팅 가능성 평가

| 항목 | 현황 | 평가 |
|------|------|------|
| CPU | ARM (GP1235, 클럭 미확인) | ARM이면 DOOM 가능 |
| LCD | 160x80 | 매우 작지만 128x64도 선례 있음 |
| Free Flash | ~284KB | 최소 DOOM WAD 압축 시 충분 |
| RAM | 미확인 (DRAM 존재 추정, 0x8C7 대역) | UART로 확인 필요 |
| 입력 | 3버튼 (전원/모드/셔터) | 최소한의 조작 가능 |
| 사운드 | 11025Hz/32000Hz WAV 재생 가능 | DOOM 효과음 가능 |

**결론**: 기술적으로 불가능하지 않지만, RAM 크기 확인과 전체 메모리맵 이해가 선행 필요.
