# DC23 / GENERAL-UVC

## 목적

이 문서는 아래 전제를 기준으로 정리한다.

- 목표: **펌웨어를 다룰 수 있는 경로**를 찾기
- 현재 상태: 분해 완료, macOS 분석 완료
- 제약: **찍찍이/포고핀/집게형 프로브 없음**

즉, 지금 당장 할 수 있는 것은

1. 사진/식별 강화
2. 버튼 조합 + USB 재열거 확인
3. SD 카드 업데이트 경로 탐색
4. Linux/Windows에서 저장장치 모드 벤더 명령 재시도 준비

정도로 보는 것이 맞다.

## 지금 기준으로 중요한 사실

- 웹캠 모드 USB ID: `1B3F:2002`
- 저장장치 모드 USB ID: `1B3F:0C52`
- 웹캠 모드 문자열에만 `Demo 1.00` 존재
- 저장장치 계층 이름은 `GENPLUS USB-MSDC DISK A`
- 보드 마킹: `DP-5307B`
- SoC 마킹: `MQ44F50.1`
- UVC Extension Unit 없음
- 웹캠/저장장치 모드에서 단순 벤더 USB 요청은 무응답

이 조합은 다음을 시사한다.

- 펌웨어는 SD 카드 파일이 아니라 **SoC 내부 저장소**일 가능성이 높다
- 그래도 **숨은 부트/다운로드 모드** 또는 **SD 카드 자동 업데이트** 경로가 남아 있을 수 있다
- `DP-5307B` / `MQ44F50.1`는 일반 모델명 `DC23`보다 훨씬 강한 추적 키다

## 놓친 점 / 결론을 약하게 잡아야 하는 부분

### 1. `UART/디버그 패드 미발견`은 결론이 너무 강함

분해 사진 기준으로는 전용 핀헤더가 없을 뿐,
**공장 테스트용으로 보이는 패드 블록은 존재한다.**

특히 의심 지점:

- SoC 위쪽의 `2x4` 금색 패드 블록
- SoC 오른쪽의 소형 패드 블록

따라서 더 정확한 표현은 아래가 맞다.

- `전용 UART 헤더는 없음`
- `용도 미확인 테스트 패드는 있음`

### 2. `외부 SPI 플래시 없음`도 아직 약간 보수적으로 봐야 함

사진상 큰 8핀 SPI NOR는 안 보이지만,
첫 번째 분해 사진에서 **SoC 왼쪽 8핀 SOIC 칩 마킹이 아직 불명확**하다.

이 칩이 아래 중 무엇인지에 따라 결론이 달라진다.

- 충전 IC / 전원 IC / 오디오 앰프
- 작은 EEPROM / config memory
- 드물지만 SPI flash

즉 현재 단계의 정확한 표현은 아래가 안전하다.

- `눈에 띄는 전형적 8핀 SPI NOR는 안 보임`
- `8핀 SOIC 미식별 칩 1개는 마킹 확인 전까지 완전 배제 금지`

### 3. `SD 전체 스캔 완료`는 raw 이미지 상태를 같이 봐야 함

현재 `diagnostics/mac_analysis/disk_image.img` 크기는 약 `2.874 GB`이고,
실제 디스크 크기는 약 `3.965 GB`다.

차이:

- 누락: `1,091,043,328 bytes`
- 약 `1040.5 MiB`

즉,

- 일부 문자열/슬랙/삭제영역 탐색 결과는 **강한 참고자료**
- 하지만 `전체 디스크에 아무 것도 없다`는 식의 **완전한 결론**으로 쓰기에는 아직 부족하다

### 4. `复位` 리셋 스위치는 아직 충분히 활용하지 않았음

보드에 `复位`가 보인다는 것은 중요하다.

이건 아래 가능성을 뜻한다.

- 부트 모드 진입 조합
- USB 다운로드 모드 진입 조합
- 버튼 조합에 따른 다른 PID/장치 클래스 노출

지금까지는 웹캠 모드 / 저장장치 모드만 본 상태에 가깝고,
**리셋 조합 실험은 아직 본격적으로 소진되지 않았다.**

### 5. `TCSYSDIR`는 아직 용도 확정 아님

이 엔트리는 단순 시스템 디렉터리일 수도 있고,
일부 펌웨어/메타데이터용 내부 관리 디렉터리일 수도 있다.

현재 시점에서는:

- 존재 자체는 의미 있음
- 하지만 이것만으로 `업데이트 디렉터리`라고 단정하면 안 됨

## 펌웨어 목표에 실제로 의미 있는 단서

### 가장 가치 높은 식별자

우선순위는 아래 순서다.

1. `MQ44F50.1`
2. `DP-5307B`
3. `Demo 1.00`
4. `1B3F:2002`, `1B3F:0C52`
5. `GENPLUS USB-MSDC DISK A`

이유:

- `DC23`는 판매명 수준이라 변형이 많다
- `MQ44F50.1`, `DP-5307B`는 실제 보드/칩에 가까운 식별자다
- 제조사/판매자/동일 보드 검색 시 가장 강한 키는 이 둘이다

### 가장 현실적인 남은 경로

1. **숨은 USB 다운로드/공장 모드**
2. **SD 카드 자동 업데이트**
3. **Linux/Windows에서 SCSI 벤더 명령 재시도**
4. **제조사/판매처 문의**

반대로 현재 확률이 낮은 경로:

- UVC 벤더 확장으로 ISP/펌웨어 직접 제어
- 외부 SPI flash 바로 덤프
- 노출된 UART 헤더에 즉시 접속

## 찍찍이 없이 지금 할 수 있는 것

### 1. 가장 먼저 할 것: 사진 보강

목표는 “전기적 작업 없이 정보량을 늘리는 것”이다.

필수 사진:

- 8핀 SOIC 칩 **매크로 3장 이상**
  - 정면
  - 좌상단 사선광
  - 우하단 사선광
- SoC 위 `2x4` 패드 블록 매크로
- SoC 오른쪽 패드 블록 매크로
- `复位` 스위치 주변 매크로
- USB 포트 주변 트레이스 매크로
- 검은 폼/스펀지 아래가 있으면 그 아래 사진
- LCD/FPC 반대쪽에 가려진 패드가 있으면 그 부분 사진

사진 팁:

- 플래시는 끄고, 옆에서 강한 조명을 비추는 편이 마킹 판독에 유리하다
- 초점이 안 잡히면 휴대폰을 조금 멀리 두고 2배 크롭이 낫다
- 같은 부품을 여러 각도에서 찍는 게 중요하다

### 2. 버튼 조합 + USB 재열거 실험

전기 측정 장비 없이도 가능한 가장 중요한 실험이다.

확인할 조합:

1. `复位` 누른 채 USB 연결
2. 촬영 버튼 누른 채 USB 연결
3. 전원 버튼 누른 채 USB 연결
4. `复位 + 촬영` 조합 후 USB 연결
5. SD 카드 삽입/미삽입 상태 각각 반복

매 조합마다 확인할 것:

- macOS에서 새 USB 장치명이 달라지는지
- `VID:PID`가 달라지는지
- 웹캠/저장장치가 아닌 다른 클래스가 뜨는지
- 아예 인식이 안 되거나 잠깐 다른 장치가 보이는지

핵심:

- 이 경로는 **펌웨어 다운로드 모드**를 찾는 실험이다
- 성공하면 가장 큰 진전이다

### 3. 메뉴 쪽 숨은 항목 재확인

장치 UI가 살아 있다면 아래 항목을 다시 본다.

- Version
- PC Camera
- U Disk / Mass Storage
- Format
- Reset
- Factory Reset
- Language
- About

특히:

- 특정 버튼을 길게 눌렀을 때 숨은 메뉴가 뜨는지
- SD 카드 꽂은 상태에서 메뉴 구조가 바뀌는지

### 4. SD 카드 업데이트 가능성 조사

지금 단계에서 가장 싸게 해볼 수 있는 펌웨어 경로다.

할 일:

- 박스/설명서/판매페이지/QR에 적힌 문자열을 가능한 한 많이 수집
- 파일명 규칙 단서가 있는지 확인
- 루트에 생성되는 특수 디렉터리/파일 패턴을 관찰

주의:

- 파일명 규칙을 모르는 상태에서 무작정 바이너리를 넣는 건 위험하다
- 우선은 **업데이트를 유발하는 이름 규칙 단서 수집**이 먼저다

## 찍찍이 없이 하기 어려운 것

아래는 지금 바로 밀어붙이기보다,
사진/버튼 조합 실험 뒤로 미루는 게 맞다.

### 1. 테스트 패드 전기적 매핑

원래는 아래를 해야 한다.

- GND 찾기
- 3.3V/1.8V 찾기
- USB D+/D- 찾기
- UART TX/RX 후보 찾기

하지만 집게/포고핀 없이 하면 접촉이 불안정해서 오판 가능성이 높다.

### 2. UART 로그 캡처

가능은 하지만,

- 전압 미확인 상태에서 바로 USB-TTL 연결은 위험
- 손으로 대면 접촉이 흔들려 로그를 놓치기 쉽다

즉 장비가 없으면 **UART는 아직 우선순위가 아니다.**

## 지금 현실적인 권장 순서

### 1단계

- 8핀 SOIC 마킹 재촬영
- 테스트 패드/리셋 주변 매크로 촬영
- 폼 아래/가려진 면 추가 촬영

이 단계의 목표:

- `외부 SPI 완전 부재`를 더 강하게 만들거나
- 반대로 `정체불명 8핀 칩`을 확정하기

### 2단계

- `复位` 포함 버튼 조합별 USB 재열거 실험

이 단계의 목표:

- 숨은 부트/다운로드 모드 존재 여부 확인

### 3단계

- 박스/설명서/판매페이지/QR 문자열 수집
- `MQ44F50.1`, `DP-5307B`, `Demo 1.00` 중심으로 제조/판매 채널 문의

이 단계의 목표:

- 공식 펌웨어 또는 업데이트 파일명 규칙 확보

### 4단계

- Linux 또는 Windows/libusb 환경에서 저장장치 모드 SCSI 벤더 명령 재시도

이 단계의 목표:

- macOS에서 못 한 벤더 통신 경로를 마지막으로 확인

## 나중에 아주 조금만 장비를 추가한다면

가성비 순서는 아래가 좋다.

1. 멀티미터 프로브 고정용 간단한 클립 또는 포고핀
2. USB-TTL 어댑터 (`3.3V` / `1.8V` 대응 여부 확인)
3. 로직애널라이저

이 중 첫 번째만 있어도 패드 매핑 난이도가 크게 내려간다.

## 최종 판단

지금 상태에서 “펌웨어를 바로 덤프한다”는 목표는 확률이 낮다.
하지만 아래 두 경로는 아직 살아 있다.

1. **숨은 USB 다운로드 모드 발견**
2. **SD 카드 자동 업데이트 규칙 확보**

그리고 그 두 경로를 열기 위해 지금 가장 중요한 작업은
**전기 작업이 아니라 사진 보강 + 리셋/버튼 조합 실험**이다.
