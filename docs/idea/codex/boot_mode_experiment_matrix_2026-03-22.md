# DC23 / GENERAL-UVC

## 숨은 부트 모드 실험표

목표:

- `1B3F:2002` 웹캠 모드
- `1B3F:0C52` 저장장치 모드

이외의 **제3의 USB 모드**가 존재하는지 확인한다.

성공 신호:

- 새로운 `VID:PID`가 뜸
- 장치명이 갑자기 달라짐
- 웹캠/U디스크가 아닌 다른 USB 클래스가 뜸
- 인식 직후 잠깐 다른 장치가 나타났다가 사라짐

## 준비

- SD 카드 `삽입` / `미삽입` 두 상태 모두 시험
- USB 케이블은 데이터 가능한 케이블 사용
- 한 번에 한 조합만 시도
- 각 실험 후 완전히 분리하고 3초 정도 기다린 뒤 다음 조합 진행

기록할 항목:

- 실험 번호
- SD 상태
- 누른 버튼
- 누른 시간
- 최종 모드
- 잠깐이라도 다른 USB 장치가 떴는지
- 새 `VID:PID`
- 비고

## macOS 확인 명령

USB 장치 확인:

```bash
ioreg -p IOUSB -w0 -l | rg -n -i '1b3f|general|genplus|mass storage|uvc|demo|disk' -C 4
```

볼륨 확인:

```bash
ls -la /Volumes
```

빠른 기록용:

```bash
date '+%F %T'
```

## 기본 기준 상태

### 기준 A: 웹캠 모드

- 예상: `GENERAL - UVC`
- 예상 VID:PID: `1B3F:2002`

### 기준 B: 저장장치 모드

- 예상: `Generic USB Mass Storage Device`
- 예상 VID:PID: `1B3F:0C52`
- 예상 볼륨: `/Volumes/SD`

이 둘 외의 결과가 나오면 **중요한 변화**로 본다.

## 권장 실행 순서

시간 대비 효율이 좋은 순서는 아래다.

1. `B03`, `B04`
2. `B09`, `B10`
3. `B05`, `B06`
4. `B11`, `B12`
5. 나머지

이유:

- 리셋 조합이 가장 부트로더/공장 모드와 가까움
- 촬영 버튼은 종종 `업데이트/다운로드` 트리거로 쓰임
- 전원 단독은 우선순위가 약간 낮음

## 관찰 포인트

### 좋은 신호

- `1B3F`는 유지되는데 PID만 바뀜
- 장치명이 비어 있거나 `USB Device`, `Bulk Device`, `HID Device`처럼 generic 하게 뜸
- `/Volumes/SD`는 안 뜨는데 USB 장치는 보임
- 기존 웹캠/저장장치 대신 전혀 다른 인터페이스 클래스가 잡힘
- 연결 직후 1초 이하로 다른 장치가 잠깐 보임

### 나쁜 신호

- 매번 완전히 동일하게 `2002` 또는 `0C52`만 뜸
- 아무 버튼 조합에서도 차이가 없음

### 애매한 신호

- 인식이 안 되는 것처럼 보이지만, 전원 LED나 화면 반응이 평소와 다름
- 장치가 잠깐 나타났다가 바로 사라짐

이 경우:

- 다시 같은 조합을 2~3회 반복
- `date`로 시간 찍고 바로 `ioreg` 확인

## 결과 해석

### 경우 1

모든 조합이 `2002` 또는 `0C52`로만 끝남.

의미:

- 적어도 버튼 조합만으로 노출되는 숨은 USB 모드는 없을 가능성이 큼
- 다음 우선순위는 `SD 카드 업데이트 규칙` 또는 `Linux/Windows SCSI 벤더 명령`

### 경우 2

새 PID가 한 번이라도 뜸.

의미:

- 가장 중요한 진전
- 해당 조합을 반복 재현해서 안정화 필요
- 그 시점의 `ioreg` 전체 출력 저장 필요

### 경우 3

인식은 안 되는데 평소와 다른 LED/화면 반응이 있음.

의미:

- 내부 부트 모드 진입 가능성 있음
- USB가 아니라 별도 타이밍/버튼 유지 시간이 필요할 수 있음

## SD 업데이트 규칙 쪽으로 바로 넘어가는 기준

아래 둘이 동시에 만족하면 부트 모드 실험은 1차 종료로 봐도 된다.

- 우선순위 높은 조합 `B03` `B04` `B09` `B10` `B05` `B06`에서 변화 없음
- SD 삽입/미삽입 차이도 없음

그 다음에는 아래를 한다.

1. 메뉴 숨은 항목 탐색
2. 박스/설명서/QR 문자열 수집
3. SD 업데이트 파일명 규칙 후보 정리
4. Linux/Windows에서 `0C52` 쪽 재시도
